# ConLaw Cases Redesign Plan

## Executive Summary

Redesign the ConLaw Cases app to use a spreadsheet-based data workflow and add structured filtering. Keep the existing Vercel/Neon infrastructure but update the data model and UI.

**Key Changes:**
1. Single Excel file as source of truth for all data
2. Controlled vocabulary tables for issues, provisions, and triggers
3. Structured filtering UI (dropdowns, year ranges)
4. Improved AI query mode with validated vocabulary
5. One import script replaces multiple seed scripts

---

### SQL Schema

```sql
-- Issues (controlled vocabulary)
CREATE TABLE issues (
  id SERIAL PRIMARY KEY,
  issue_id VARCHAR(20) UNIQUE NOT NULL,  -- e.g., "I01"
  name VARCHAR(200) NOT NULL,             -- e.g., "Commerce Clause"
  description TEXT
);

-- Provisions (hierarchical)
CREATE TABLE provisions (
  id SERIAL PRIMARY KEY,
  provision_id VARCHAR(50) UNIQUE NOT NULL,  -- e.g., "14A.S1.Cit"
  parent_id VARCHAR(50) REFERENCES provisions(provision_id),
  name VARCHAR(200) NOT NULL,                 -- e.g., "Citizenship Clause"
  full_text TEXT
);

-- Triggers (events that caused cases)
-- Note: trigger_id changes from integer to string format
CREATE TABLE triggers (
  id SERIAL PRIMARY KEY,
  trigger_id VARCHAR(20) UNIQUE NOT NULL,  -- e.g., "T001"
  trigger_type VARCHAR(100),
  trigger_event VARCHAR(500) NOT NULL
);

-- Cases (simplified - no more issues array)
CREATE TABLE cases (
  id SERIAL PRIMARY KEY,
  name VARCHAR(500) NOT NULL,
  year INTEGER NOT NULL,
  description TEXT NOT NULL,
  chief_justice_id INTEGER REFERENCES chief_justices(id),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- Junction tables
CREATE TABLE case_issues (
  case_id INTEGER REFERENCES cases(id) ON DELETE CASCADE,
  issue_id VARCHAR(20) REFERENCES issues(issue_id) ON DELETE CASCADE,
  PRIMARY KEY (case_id, issue_id)
);

CREATE TABLE case_triggers (
  case_id INTEGER REFERENCES cases(id) ON DELETE CASCADE,
  trigger_id VARCHAR(20) REFERENCES triggers(trigger_id) ON DELETE CASCADE,
  PRIMARY KEY (case_id, trigger_id)
);

CREATE TABLE case_provisions (
  case_id INTEGER REFERENCES cases(id) ON DELETE CASCADE,
  provision_id VARCHAR(50) REFERENCES provisions(provision_id) ON DELETE CASCADE,
  PRIMARY KEY (case_id, provision_id)
);

-- Updated view with all relationships
CREATE VIEW cases_view AS
SELECT
  c.id,
  c.name,
  c.year,
  c.description,
  c.chief_justice_id,
  cj.name as chief_justice_name,
  cj.start_year as chief_justice_start,
  cj.end_year as chief_justice_end,
  ARRAY_AGG(DISTINCT i.name) FILTER (WHERE i.name IS NOT NULL) as issues,
  ARRAY_AGG(DISTINCT i.issue_id) FILTER (WHERE i.issue_id IS NOT NULL) as issue_ids,
  ARRAY_AGG(DISTINCT t.trigger_type) FILTER (WHERE t.trigger_type IS NOT NULL) as trigger_types,
  ARRAY_AGG(DISTINCT t.trigger_event) FILTER (WHERE t.trigger_event IS NOT NULL) as trigger_events,
  ARRAY_AGG(DISTINCT p.name) FILTER (WHERE p.name IS NOT NULL) as provisions,
  ARRAY_AGG(DISTINCT p.provision_id) FILTER (WHERE p.provision_id IS NOT NULL) as provision_ids
FROM cases c
LEFT JOIN chief_justices cj ON c.chief_justice_id = cj.id
LEFT JOIN case_issues ci ON c.id = ci.case_id
LEFT JOIN issues i ON ci.issue_id = i.issue_id
LEFT JOIN case_triggers ct ON c.id = ct.case_id
LEFT JOIN triggers t ON ct.trigger_id = t.trigger_id
LEFT JOIN case_provisions cp ON c.id = cp.case_id
LEFT JOIN provisions p ON cp.provision_id = p.provision_id
GROUP BY c.id, c.name, c.year, c.description, c.chief_justice_id,
         cj.name, cj.start_year, cj.end_year;
```

## Part 3: Import Script

### Single Command
```bash
npm run import
# or
npx tsx scripts/import-spreadsheet.ts conlaw-data.xlsx
```

### Script Behavior
1. Read all sheets from Excel file
2. Validate data:
   - All issue_ids in Cases exist in Issues sheet
   - All trigger_ids in Cases exist in Triggers sheet
   - All provision_ids in Cases exist in Provisions sheet
   - All parent_ids in Provisions exist
   - No duplicate IDs
   - Required fields present
3. Report validation errors (don't proceed if errors)
4. Clear existing data (in correct order for foreign keys)
5. Insert reference tables: chief_justices, issues, triggers, provisions
6. Insert cases (lookup chief_justice_id by year)
7. Insert junction tables: case_issues, case_triggers, case_provisions
8. Report success with counts

Add a filter panel to Query Builder:

```
┌─────────────────────────────────────────────────────────────┐
│  Filter Cases                                                │
├─────────────────────────────────────────────────────────────┤
│  Issues:        [Commerce Clause      ▼] [+ Add]            │
│                 [Equal Protection     ▼] [×]                │
│                                                              │
│  Provisions:    [14th Amendment       ▼] [+ Add]            │
│                                                              │
│  Year Range:    [1900] ────●──────────── [2024]             │
│                                                              │
│  Chief Justice: [Any                  ▼]                    │
│                                                              │
│  Text Search:   [________________________]                  │
│                                                              │
│  [Search]                              [Clear Filters]       │
└─────────────────────────────────────────────────────────────┘
```

- Dropdowns populated from database via `/api/schema-info`
- Multi-select for issues and provisions
- Results shown below, same card format as now
- No AI involved - deterministic SQL generation from filter state

### AI Query Mode (Improved)

Keep the natural language input but improve it:

1. Fetch controlled vocabulary on page load
2. When AI generates SQL, validate issue/trigger/provision names against known values
3. If AI uses unknown value, fuzzy-match to closest valid value
4. Show user what was matched: "Interpreted 'free exercise' as 'Free Exercise Clause'"

### Tab Structure

```
[Structured Search] [AI Query] [Chat/RAG]
```

- **Structured Search**: New filter-based UI (default)
- **AI Query**: Natural language → SQL (current Query Builder, improved)
- **Chat/RAG**: Semantic search + AI response (current Chat Interface)

## Part 5: Transition Plan

### What to Keep
- **Vercel project**: Same deployment, same URL
- **Neon database**: Same instance, update schema
- **GitHub repo**: Continue in same repo
- **Next.js app structure**: Pages, API routes, components
- **shadcn/ui components**: Cards, buttons, inputs, etc.
- **AI provider integrations**: Anthropic, OpenAI, Gemini, OpenRouter

### What to Remove
- `con-law-cases.json` → replaced by spreadsheet
- `trigger-table.json` → replaced by spreadsheet
- `case-trigger-junction-table.json` → replaced by spreadsheet
- `scripts/seed-cases.ts` → replaced by import script
- `scripts/seed-triggers.ts` → replaced by import script
- `scripts/seed-case-triggers.ts` → replaced by import script
- `scripts/reseed-cases.ts` → replaced by import script
- Old `issues` TEXT[] column in cases table

### What to Modify
- Database schema (add tables, modify cases table)
- `lib/schema.ts` (update for new structure)
- `app/api/schema-info/route.ts` (add provisions, issues from tables)
- `components/QueryBuilder.tsx` (add structured filtering)
- `lib/ai/providers.ts` (improve prompts with validated vocabulary)

### Migration Steps

#### Phase 1: Prepare Data (Local)
1. Create `conlaw-data.xlsx` template
2. Export current data from database to populate sheets
3. Create Issues sheet from current distinct issues
4. Fix Triggers sheet (resolve duplicates, clean data)
5. Create Provisions sheet (new - requires research/entry)
6. Verify Cases sheet with new ID references

#### Phase 2: Update Code (Branch)
1. Create branch: `git checkout -b redesign`
2. Add new database schema migration script
3. Build import script (`scripts/import-spreadsheet.ts`)
4. Update `lib/schema.ts` for new structure
5. Update `/api/schema-info` endpoint
6. Build Structured Search component
7. Update Query Builder with validation
8. Test locally with new data

#### Phase 3: Deploy
1. Run schema migration on Neon (add new tables)
2. Run import script with spreadsheet
3. Verify data in database
4. Deploy updated code to Vercel
5. Test production
6. Delete old JSON files and seed scripts
7. Merge branch to main

### Rollback Plan
- Keep old tables until new system verified
- Old JSON files remain in git history
- Can revert Vercel deployment instantly
- Database can be restored from Neon backups
